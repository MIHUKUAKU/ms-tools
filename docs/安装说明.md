# Windows / PCL 安装说明

## 准备

先在 PCL 创建并启动过 Minecraft 26.2 或 26.3 的 Fabric 版本，确认 Java 与 Fabric Loader 符合包内 jar 的元数据。关闭游戏，再将整个发布 ZIP 解压到普通文件夹（不要直接在压缩包预览里运行）。

双击 `installer/Install.cmd`，填写的路径应是 PCL 的**版本文件夹**，例如 `D:\...\versions\26.3-Fabric 0.19.5`，而不是 `.minecraft`、`mods` 或 `saves` 文件夹。安装器会识别版本名或版本 JSON 中的 Fabric 和 26.2/26.3 信息；无法识别时会停止。若是 MS 或两者模式，选择 `saves` 下含 `level.dat` 的存档。只装刷交易时无需选择存档。

模式 `MS` 安装 Carpet、`mstrade` 和四个脚本；模式 `Trade` 安装刷交易模组、Fabric API、Trade Cycling、Visible Traders；模式 `Both` 安装两组。前置从 [Modrinth](https://modrinth.com/) 按游戏版本及 Fabric 平台查找正式版，下载后与 Modrinth 提供的 SHA-512 比对，并检查 jar 的 Fabric ID。网络故障、无对应正式版、校验失败都会在写入实例前停止。安装器**不会安装 Fabric Loader 或 Java**。

## 安装器做什么

- 从 ZIP 的 `payload/mods` 读取本包 jar，从 `payload/scripts` 读取四个 `.sc`。缺文件会直接报错。
- 安装 MS 时把 `commandPlayer true` 和 `scriptsAutoload true` 合并到所选存档的 `carpet.conf`；保留其它设置。Scarpet 脚本自身已开放 `players` 命令权限，普通玩家不需 OP。
- 读取现有 `mods/*.jar` 内的 `fabric.mod.json`，只挑选本次安装涉及的模组 ID 做备份、替换。无关 jar 不动。四个同名脚本及 `carpet.conf` 的原件也备份。
- 备份保存在该版本目录的 `.ms-tools-backup/日期-随机号` 下。保留备份，直到游戏启动并确认功能正常。
- 不改动任何 `.data.nbt`、交易链 JSON、玩家背包数据、其它存档文件、其它模组。失败时安装器尝试回滚本次移动和新文件；若回滚也遇到文件占用，请从显示的备份目录手动还原。

## 自己手动装

不想运行安装器的话，先退出游戏：

1. 下载当前 Minecraft 版本对应的 Fabric 前置。MS 要 [Carpet](https://modrinth.com/mod/carpet)；刷交易要 [Fabric API](https://modrinth.com/mod/fabric-api)、[Trade Cycling](https://modrinth.com/mod/trade-cycling) 和 [Visible Traders](https://modrinth.com/mod/visible-traders)。
2. 把需要的自制 JAR 和前置放进这个 Fabric 实例的 `mods`，同一个模组别留两份。旧 JAR 先移到实例之外备份。
3. 装 MS 时，把安装 ZIP 的 `payload/scripts` 里的 `ms.sc`、`fetch.sc`、`put.sc`、`throw.sc` 放进目标存档的 `scripts`。旧同名脚本先备份，别覆盖或删除 `.data.nbt` 和交易链 JSON。
4. 在该存档的 `carpet.conf` 中设置 `commandPlayer true` 和 `scriptsAutoload true`，其它规则保留。没有这个文件就新建普通文本文件，注意不要存成 `carpet.conf.txt`。
5. 重启对应实例并进入目标存档。只装刷交易时无需复制脚本或修改 Carpet 规则。

全套命令见 [全部命令](全部命令.md)，和平机和回家的实际用法见 [使用示例](使用示例.md)。

需要先看计划而不写入，可用 PowerShell：

```powershell
./installer/Install.ps1 -InstancePath 'D:\mc\GAME\GAME\versions\26.3-Fabric 0.19.5' -WorldName 'myworld' -Mode Both -DryRun
```

`-Mode` 可为 `MS`、`Trade`、`Both`。DryRun 仍会联网下载到系统临时目录完成校验，但不会修改游戏实例。

无人值守部署或隔离测试可加 `-Yes` 跳过最后的 `YES` 确认提示；须同时传入实例路径、模式，以及 MS 模式所需的存档名。`-Yes` **不会**检查或自动关闭游戏，也不会跳过下载/哈希/路径检查：运行前仍必须自己确认游戏已完全退出。普通用户建议直接用 `Install.cmd` 交互确认。

## 安装后

重新启动 PCL 中对应的 Fabric 版本。MS 模式进入所选世界后直接输入：

```text
/ms
```

安装器设置 `scriptsAutoload true`，四脚本设有 `stay_loaded`，应自动加载。如世界重开后 `/ms` 消失，让有权限的管理员先看 Carpet/Scarpet 日志，必要时用 `/script load ms`、`/script load fetch`、`/script load put`、`/script load throw` 排错；普通生存玩家不应被要求执行这些管理命令。`/ms collect`、`/ms craftbox`、`/ms trade ... keep` 需要本包 `mstrade` 成功加载。`/ms` 普通玩家使用依赖 Scarpet 的 `command_permission=players` 和世界的 `commandPlayer true`；服务器有其它权限插件时仍可能另有约束。

刷交易模式安装后打开村民交易界面，等待 Visible Traders 的高级交易预览完整显示，点「筛选设置」选择物品/附魔/药水效果、价格和序号，**保存**，重新打开该村民的交易界面，点「筛选：开始」。关闭交易窗口或点「停止」可中止。只在单人存档工作；不自动购买。

## 排错

| 症状 | 检查 |
| --- | --- |
| 报找不到 Fabric 版本 | 路径必须指向 PCL 的具体 26.2/26.3 Fabric 版本文件夹；版本 JSON/文件夹名需能识别。 |
| 报前置无对应版本或 SHA-512 失败 | 检查网络后重试；不要从未知站点手工替换为其它游戏版本 jar。 |
| 游戏启动报模组版本不符 | 先确认 ZIP 内两个自制 jar 的 `fabric.mod.json` 是否确实声明当前游戏版本；此时不要强装。 |
| `/ms` 不存在 | 检查 Fabric Carpet 已加载、`scriptsAutoload true` 生效、世界 `scripts` 中有四个脚本；让管理员看日志或手动执行 `/script load ms` 排错。 |
| 假人指令权限不足 | 看世界 `carpet.conf` 是否有 `commandPlayer true`；脚本是否是本包版本。无需给普通玩家 OP。 |
| 刷交易按钮不出现 | 检查 Fabric API、Trade Cycling、Visible Traders 与刷交易 jar 已加载，且打开的是村民交易界面；刷交易只支持单人。 |

卸载时先退出游戏，只移除本包模组 ID 对应 jar 和四个脚本；是否恢复旧版本，请从 `.ms-tools-backup` 按相对路径复制回去。若想保留自己后来修改过的脚本或 `carpet.conf`，不要直接覆盖，先手工比较。不要删除 `.data.nbt` 与交易链 JSON，它们是用户数据。
