# 两个常用例子：和平机开关和远程回家

我最早做这个就是想开关和平机，下面先用这个说明。所有坐标都是示例，要换成你自己的；命令里的编号和名字也可以自己改。

## 例子一：用一个短指令开关和平机

先把和平机和控制它的拉杆/按钮建好。MS 做的事是让假人在固定位置右键机关，不是把游戏难度改成和平，也不会直接替你造机器。

### 1. 记下右键机关的位置

自己站在假人应该站的位置，把准星对准拉杆或按钮，保证可以右键到。用 F3 记下脚下的 `XYZ`、水平角度 `yaw` 和俯仰角度 `pitch`；录入时也可以按 Tab 补全。

假设这个位置是主世界 `100.5 64 100.5`，朝向为 `0 0`，就存成编号 1：

```text
/ms add 1 SwitchBot 100.5 64 100.5 0 0 overworld
/ms list 1
```

`SwitchBot` 是假人名字，`1` 是预设编号。后面调用用编号，不用重新输入名字和坐标。不要直接照抄角度：假人要能看见并够到你自己的机关。

### 2. 调用这个开关

```text
/ms walk 1
```

假人生成，右键一次，停留约 20 gt（正常 TPS 下约 1 秒）后退出。我的机器有加载器，给它留一点启动时间用 `walk` 更合适。

机器不需要这段停留时间时，也可以用：

```text
/ms run 1
```

`run` 右键后约 4 gt 退出。`keep` 只上线、不会右键，别把它当开关用。录入后第一次调用请先保证这个假人离线；已经在线时，会用它当时的位置，不会强制回到预设点。

### 3. 怎么分开“开”和“关”

如果机器用同一个拉杆切换状态，重复 `/ms walk 1` 就是再切换一次；MS 不会自动判断机器现在开着还是关着。

如果机器有两个独立按钮，可以分别记录“开”的位置为 1、“关”的位置为 2，之后：

```text
/ms walk 1
/ms walk 2
```

执行反馈表示假人做了右键动作，不保证红石机器实际完成了切换。可以在控制端接一盏状态灯，第一次确认好再远程用。

## 例子二：在远处触发家里的珍珠，回家

这里说的“回家”是让**玩家本人**回家，需要先有一个可用的末影珍珠滞留装置。MS 负责让假人在家里加载机关并右键释放珍珠，不是直接传送真人的指令。

### 1. 准备家里的装置

- 自己把一颗末影珍珠放进家里的滞留装置。
- 把释放机关接到假人能右键的拉杆/按钮。也可以直接对准能释放珍珠的活板门，具体以自己的装置为准。
- 假人的生成位置要安全，并能加载珍珠和机关所在区域；两者别离得太远。

假设触发位置在主世界 `200.5 64 200.5`，朝向为 `90 0`，存成编号 2：

```text
/ms add 2 HomeBot 200.5 64 200.5 90 0 overworld
/ms list 2
```

同样，把示例坐标和角度换掉。这个编号只是例子，若 2 已经被和平机关机按钮用了，就换一个空编号，比如 10。

### 2. 出门后远程触发

人在远处、珍珠还留在装置里时输入：

```text
/ms walk 2
```

`HomeBot` 会在保存的位置上线，加载附近区域并右键释放机关，随后退出。装置正常、珍珠仍然有效时，珍珠触发后就会把它的主人带回来。

先在主世界近距离试好整套装置，再逐步尝试更远距离。跨维度回家是否可用还取决于当前 Minecraft 的珍珠机制和装置设计，这里没有单独验证，不保证在任何维度都能成功。

珍珠已经消耗、装置没重新装好，或者假人生成/右键失败，都不会让你凭空回家。每次成功使用后，记得重新放入自己的珍珠，并把机关复位。

### 补充：如果只是让假人带东西回来

这才是 `send` 的用途。比如在线的 `Courier` 已在仓库前，可以让它取货再回到你这里：

```text
/ms fetch Courier
/ms send Courier
```

`fetch` 不带目标玩家时只取货，不移动；`send` 不带目标玩家时，假人下线后在命令执行者的位置重新上线。取货动作完成后再发 `send`，别把两条当成一个原子操作。

也可以直接写接收玩家：

```text
/ms fetch Courier Alex
```

这里 `Alex` 必须在线；假人取货后会尝试送到 Alex 身边。名字按你的实际玩家名填写，可以用 Tab 选。

**`send` 搬的是假人和它携带的物品，不是玩家本人。**
