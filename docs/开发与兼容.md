# 开发与兼容

两个子项目独立构建、独立安装。使用 JDK 25：

```powershell
.\gradlew.bat build --console=plain
```

输出分别位于 `ms-tools/build/libs` 和 `trade-target/build/libs`；名称带 `-sources` 的是源码，不要装进游戏。
`trade-target:logicTest` 运行 126 项匹配、价格、序号与配置持久化检查。

默认编译环境为 26.3。编译依赖的精确版本仅用于可复现构建，不等于运行时只能使用这些前置版本。
运行时支持范围为 Minecraft 26.2 / 26.3、Fabric Loader >= 0.19.3、Java >= 25；
Trade Cycling >= 1.0.21、Visible Traders >= 2.5.0。前置必须本身支持当前 Minecraft 版本。

验证 26.2 编译可执行：

```powershell
.\gradlew.bat clean build '-Pminecraft_version=26.2' '-Ploader_version=0.19.3' '-Pfabric_api_version=0.153.0+26.2' '-Ptrade_cycling_version=Pw2HCuRa' '-Pvisible_traders_version=2.5.0'
```

`McCompat` 只桥接两个版本间的挥手与世界时钟接口变更；路径使用两版共有的碰撞体接口。
没有将 Minecraft 版本设为 `*`，以免向未经测试的版本承诺兼容。

发布源码不包含任何存档、玩家背包、坐标预设、交易路线或个人账号配置。
第三方依赖通过 Fabric Maven / Modrinth 获取，安装包不将第三方模组冒充为本项目作品。

构建后运行 `python tools/package.py`，在 `dist` 生成两个独立 JAR、Windows 安装 ZIP 与 SHA-256 清单。准备1.7.4安装包前，显式运行 `python tools/fetch_installer_dependencies.py` 获取并审核官方前置与许可证；准确版本写入 `installer/dependencies.json`，不将Trade Cycling JAR打进ZIP。安装发行版号1.7.4与沿用的功能JAR版本分开记录。
GitHub Actions 会在推送 main、推送 `v` 开头标签或提交 PR 时编译两版并执行逻辑检查，也支持手动触发。工作流仅使用只读仓库权限，不会自动创建 Release 或修改现有附件；在线构建结果以仓库 Actions 页面为准。
仓库需要 GitHub 登录与写权限，首次推送前应确认仓库归属和可见性。

参考：[Fabric Loom](https://docs.fabricmc.net/develop/loom/)、
[Modrinth 版本查询 API](https://docs.modrinth.com/api/operations/getprojectversions/)、
[GitHub setup-java](https://github.com/actions/setup-java)。
